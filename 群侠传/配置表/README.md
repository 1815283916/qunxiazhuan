# 配置表

以下工作簿为 `.xlsx` 格式，可使用 Excel、WPS 或 LibreOffice 编辑。每个文件包含一张同名工作表，表头已冻结并启用筛选，文本字段已设置自动换行。

| 文件 | 内容 |
| --- | --- |
| `武学.xlsx` | 武学的内力消耗、威力、范围、形状、图标、特效资源和描述 |
| `心法.xlsx` | 心法等级、攻防成长、经验需求和描述 |
| `人物属性.xlsx` | 当前六名可用人物的初始属性、模型、武学和心法等级 |
| `装备.xlsx` | 装备槽位及各项属性加成；无加成为 0 |
| `成长规则.xlsx` | 人物、武学、心法的升级与战斗经验规则 |
| `物品.xlsx` | 16 种物品的 ID、分类、价格、上架开关、图标、秘籍技能、药效和获取说明 |

人物属性表中的人物编号用于配置识别。武学列表与等级列表使用 `|` 分隔，等级项格式为 `武学名称:等级`。资源列填写 `res://` 项目路径；武学特效资源指向包含连续 PNG 帧的目录，支持 `1.png` 或 `01.png` 起始编号；数值加成列均为数字。

这些工作簿是人物、装备、武学、心法与成长规则的数据来源。修改后在 Godot 项目目录运行：

```powershell
python tools/export_config.py
python tools/export_config.py --check
```

工具只使用 Python 标准库。导出时检查重复 ID、名称、人物技能引用、技能等级、装备槽位和资源路径；校验失败时保留已有运行配置。`--check` 只检查配置是否与表格一致，不写入文件。游戏从 `data/configuration.json` 加载配置，提交修改时应同时提交表格与生成的 JSON。

成长规则支持非负整数、`当前等级×整数` 和 `整数×人物悟性`；当前导出器不执行任意 Excel 公式。人物界面目前固定为六名侠客，程英初始没有武学，出战前需从背包研习秘籍。

武学、心法、装备和人物 ID 必须保持稳定。当前版本 3 存档按 ID 分开保存已学和已装备技能，修改名称、调整人物表顺序后可正常恢复；ID 应使用小写字母、数字和下划线，以字母开头。版本 0/1/2 旧档兼容迁移，再次保存后升级为版本 3。

人物表中的“初始武学”和“初始心法”定义初始装备，也会加入已学列表。装备最多四个武学和一个心法；后续研习可继续增加已学技能，不受装备栏数量限制。

物品表中的买价、卖价均为银两整数，卖价不能高于买价；“商店出售”为 1 时上架供购买，为 0 时不上架，但背包中的同名物品仍可按卖价出售。装备行的 ID 与名称必须匹配装备表；物品图标统一以物品表为准，装备表图标保留为兼容回退。秘籍的技能 ID 指向武学或心法表，学习后不消耗秘籍。药品的“恢复气血 / 恢复内力”直接用于战斗，其他类别这两列必须填 0。“获取途径”是物品详情中的说明文字，不会自动新增任务或掉落事件。修改后仍运行 `python tools/export_config.py`。

删除一行会移除其运行配置，导出前应同时清理人物表中的相关技能与等级引用。旧档中已删除的装备、武学 ID 会被清理，心法缺失时回退到当前配置中可用的心法。

剧情由 `剧情配置.json` 管理，直接读取项目根目录 `剧情.txt` 后半扩写的十二场剧本。运行 `python tools/export_story.py` 生成 `data/story.json`，加 `--check` 检查是否同步。原稿不被改写。

- `nodes`：按原稿顺序的 25 个游玩节点。`id` 是存档引用，不随标题修改；`chapter` 对应原稿场次，`location` 对应具体场所。
- `source_span`：在该场原稿中从 `start`（含）到 `stop`（不含）的【说话人】记录，编号从 0 开始。484 条记录必须各绑定一次，缺段或重复都禁止导出。
- `source_edits`：13 条有明确原因的显示替换，包括涉及性暴力、未成年人性暗示的非露骨转换，以及 3 处明显说话人/称谓误标校正。除此之外对白与旁白逐字读取原稿。输出的 `source_coverage` 和每条 `source_lines` 可核对覆盖与出处。
- `dialogues`：通常由原稿绑定自动生成；章节结束的系统提示单独配置，并明确标为“章节结束”，不冒充原稿对白。正文修改后重新导出即可；增删记录后须调整 `source_span`。
- `automatic`：战斗后的原文对话自动续接；`interlude`：剑冢之后的药王庄插叙。战斗结算不跳过后续对白。
- `locations`：17 处具体场所的名称、`parent`（上级区域 ID）、`local_name`（简称）、背景、介绍及商店开关，分别按主线解锁。白马寺镇、药王庄归洞庭，不按现实洛阳白马寺改写原稿地点；新增姑苏沿途客栈承接旅途原文。
- `regions`：8 个上级区域；背景、简介、`map_position`（1600×900 画布上的坐标）按山水示意图摆放。区域 ID 不得与具体场所 ID 重复。
- `encounters`：三场交互战斗的敌人、人数、属性、奖励和背景。冲突的原文结果与对话在战后节点继续。
- `join` 在战前生效，`leave` 在对应剧情节点完成后生效并归还借用装备。数值对应现有六个人物槽位；胡夫人与黄蓉为临时同伴，其余人物作为 NPC。
- `heal`：神照经全篇事件，续接经脉，学习并装备神照经。`money` / `items` 为节点奖励；回顾对白不会重复发奖。
- `profiles`、`skills`、`items`、`initial`：主线人物身份、专用心法与纪念物、开局资源；基础人物 ID 继续沿用以保留旧档养成。
- `world_map` 指定大地图素材与区域入口尺寸；`profiles[].head` 同步人物各页面，`portraits` 配置其余 NPC 头像。

大地图只显示区域，进入后查看所属具体场所。至少一处场所开放后即可进入其区域，但不会一并解锁其他场所。返回逐级导航，任务逐级高亮。存档仍使用原有具体场所与节点 ID，旧进度继续保留；想完整阅读新增的前序原文，可开始新游戏。新增后续节点时不要删除或重用已发布 ID。

对话界面按字符边界自动分屏，保留所有字符并支持上一页；源记录与显示页不一一对应。顶栏样式集中在 `scripts/top_bar.gd`。
